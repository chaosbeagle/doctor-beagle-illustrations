# Composition Patterns and Originality Rules

Choose one structure. Do not combine too many systems in one image.

## Structure Types

### Workflow

Use for input -> processing -> output, content production, AI workflows, and automation chains.

Draw input on one side, a strange low-tech process in the middle, and output on the other side. Doctor Beagle should pull, push, carry, sniff, or operate the main transition. Use orange for the main path.

### System Fragment

Use for information sources, filters, databases, renderers, agent loops, and partial systems.

Draw only 3-5 core modules. Doctor Beagle participates in one key action, not every module.

### Before/After Contrast

Use for chaos/order, manual/automatic, scattered/collected, anxious/stable.

Draw left as messy, right as stable, with a restrained orange transition. Keep it sketch-like, not a formal comparison chart.

### Character State

Use for user pain, creator state, tool overload, information anxiety, stuck-to-moving transitions.

Draw 2-4 small states, each with one short label. Doctor Beagle's posture should carry the feeling.

### Concept Metaphor

Use for content factories, signal wells, idea machines, knowledge boxes, black-box processes, and daily automation.

Draw one memorable low-tech object or strange machine, a small input, and a small output.

### Method Layers

Use for frameworks, capability stacks, content systems, operating layers.

Draw stacked boxes, drawers, shelves, or low-tech layers. Avoid official pyramids.

### Map or Route

Use for idea-to-launch paths, user journeys, content handoff, learning paths.

Draw one curved path with a few nodes. Doctor Beagle can pull the route, sniff the trail, or carry a missing connection.

### Mini Comic

Use for failure-to-success, real process, light commentary, before/after behavior.

Draw 2-4 tiny scenes. Each panel should express one action.

## Fresh Metaphor Method

Invent from the current article. Do not reuse old examples by default.

1. Convert the abstract concept into a physical action: stuck, leaking, heavy, sorting, fermenting, opening, folding, unpacking, returning, bridging.
2. Convert the system into one low-tech object: broken machine, paper box, drawer, pipe, mailbox, scale, well, ladder, thread, gate, turntable, odd workstation.
3. Make Doctor Beagle perform the action: pull, carry, sniff, sort, guard, push, repair, weigh, tug, catch, tag, wait, or lie flat.

## Object Pool

Use 1-2 objects only:

- paper box, drawer, old machine, funnel, scale, mailbox, door, well, ladder, pipe, thread ball, gate, turntable, black box, hole punch, press, clothesline, strange desk.

## Doctor Beagle Action Pool

- pull, carry, sniff, push, guard, sort, tag, tug, repair, hold, sit, wait, lie flat, nudge, fetch, bridge, collect.

The action must serve the concept. Do not be strange for its own sake.

## Repeat-Avoidance Rules

Do not default to old Xiaohei compositions, old generated beagle sheets, or bundled visual anchors as article compositions. The reference sheets are only for character consistency.

Unless the user explicitly asks to replicate a specific image, do not reuse:

- beagle model-sheet poses as final article scenes
- beagle action-sheet poses without adapting them to the article
- beagle beside a generic machine without a fresh metaphor
- a route/path image for every handoff concept
- a simple left-input/right-output workflow for every automation concept

For similar topics, change the core object and beagle action. For example, a "handoff path" can become Doctor Beagle stitching a loose thread to a doorknob, not always walking a route.
